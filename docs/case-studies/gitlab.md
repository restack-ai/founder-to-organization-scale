# Case Study: GitLab

GitLab is one of the clearest public examples of a write-first, distributed operating system.

## Relevant practices

- Directly Responsible Individual (DRI)
- Two-phase decision-making: gather data, then decide
- TeamOps
- Handbook-first documentation
- Measurement clarity
- Async-first collaboration

## Why it matters

GitLab's model shows that distributed decision-making is not the absence of structure. It is structure moved into writing, role clarity, and measurable outcomes.

The important pattern is:

```text
Context is public → owner is clear → decision can move without waiting for hierarchy
```

## Lessons for startups

1. One clear owner beats broad committee ownership.
2. Written context lets decisions scale beyond personal access to the founder.
3. Data gathering and decision ownership should be separated.
4. A decision can be collaborative in input but individual in accountability.
5. Remote and async work force clarity that office-based teams often avoid.

## Repo application

Use the GitLab pattern for:

- decision logs;
- operating handbooks;
- DRI assignment;
- async decision review;
- KPI-driven accountability.
