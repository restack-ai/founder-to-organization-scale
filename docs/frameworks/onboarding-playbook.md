# Onboarding Playbook for Ownership

Ownership is trained, not announced.

The goal of onboarding is not only to teach tools and processes. It is to teach how the company makes decisions.

## 30 / 60 / 90 day path

| Phase | Outcome required | Artifacts |
|---|---|---|
| First 30 days | Understand mission, values hierarchy, decision-rights map, escalation rules, and how decisions are documented. | Readme, decision rights map, sample decision records |
| Days 31–60 | Own one bounded project as DRI or Driver. Run one context review. Publish one retrospective. | Delegation contract, project decision record, retro |
| Days 61–90 | Make one independent cross-functional decision inside guardrails. Present tradeoffs, metrics, and recommendation in writing. | DACI / DRI record, KPI note, review memo |

## What new hires must learn

- What decisions are centralized and why.
- Which decisions they are expected to own.
- How to document a decision.
- How to disagree and commit.
- When to escalate.
- How AI agents may be used and where human approval is required.

## Manager checklist

- [ ] Assign first decision owner role within 30 days.
- [ ] Provide a sponsor for first decision memo.
- [ ] Review one real decision from history.
- [ ] Explain the founder's taste, but separate taste from policy.
- [ ] Define what "good judgment" looks like in the role.
- [ ] Review escalation examples.
- [ ] Confirm the new hire knows which AI tools are allowed.

## Anti-pattern

Do not onboard people by saying: "Ask me whenever you're unsure."

That sounds supportive, but it can train dependency. Better:

> "Make the smallest safe decision you can. Write the tradeoff. Escalate only when the risk crosses the threshold we defined."
